The CSI bottleneck: pilots grow with elements × users

Illustrative
Electronic RIS: the cascaded channel of every element to every user must be estimated; pilot time grows with $N \times K$ and eats the coherence window.
Mechanical reflector array: the controller needs only the $K$ user positions; its input does not grow with the number of tiles $N$.

Watch the orange part of the bar on the left. It represents time spent sending pilots to estimate channel state information, or CSI. In this example, the controller estimates a channel through each surface element to each user. As the grid gets finer, that number grows as elements times users. The channel is stable for only a limited time, so the green part available for data shrinks.

On the right, adding tiles still leaves us with the same three user positions. That's the information our controller uses to steer the surface.

An electronic reconfigurable intelligent surface, or RIS, steers a wave by changing the phase response of its elements. The array on the right steers it by physically turning metal tiles. Each tile is large compared with the wavelength, so we can calculate its orientation using the law of reflection.

This changes the engineering trade-off. The tiles need power to move and can hold their position afterward. Mechanical motion takes time, so slowly changing indoor links are a natural starting point. Steering also depends on knowing where the users are.

Bisector rule: each tile normal splits AP and user directions

Illustrative

Tile center A, AP at B, user at C. Law of reflection:

$$\vec n=\tfrac12\Big(\tfrac{\overrightarrow{AB}}{|\overrightarrow{AB}|}+\tfrac{\overrightarrow{AC}}{|\overrightarrow{AC}|}\Big)$$

Only positions enter; no channel estimate.

Normals: angle in = angle out at every tile, so all reflected rays meet at the user.

MA-MDP: each agent moves the focal point of one segment

Array partitioned into $L$ disjoint segments $\mathcal{T}_l$; agent $l$ controls focal point $f_{l,t}\in\mathbb{R}^3$.

  • State: $s_t=[u_{1,t},\dots,u_{K,t},\,r_{1,t},\dots,r_{L,t},\,f_{1,t},\dots,f_{L,t}]$user positions, segment centers, focal points
  • Local observation: $o_{l,t}=[u_{b_l,t},\,r_{l,t},\,f_{l,t}]$; assigned user $b_l$ fixed in advance
  • Action: $a_{l,t}\in\mathbb{R}^3$, $\|a_{l,t}\|_\infty\le\delta_{\max}$, $\;f_{l,t+1}=f_{l,t}+a_{l,t}$
  • Shared reward: $R(s_t,a_t)=\frac{1}{K}\sum_{k=1}^{K}P_{r,k}(s_t,a_t)$ (RSSI)
  • Focal points clipped to $\mathcal{F}_l$, angles to $\pm30^\circ$: every action feasible

Run time: positions only; training: received power as the reward. No pilot-based CSI estimation.

[1.25 min | 13:30–14:45]

Consider one control step from the point of view of the blue segment. Its agent observes three positions. The first tells it where its assigned user is. The other two tell it where its segment sits and where it is aiming now. Its action is a displacement of the focal point in three dimensions. We bound each component of that displacement, keep the focal point within its allowed region, and clip the resulting tile angles to the servo limits.

We formulate this as a cooperative multi-agent Markov decision process. During training, all agents get the same reward, the mean received signal strength across the users. A move that helps one user can therefore affect the reward for the whole team. At deployment each agent chooses its move from local positions. The user assigned to that segment stays fixed for this first controller.

From fixed assignment to learned allocation

Two corner arrays: a user can be served by segments with very different geometry, so the assignment now matters.

Serving $K$ users with $L$ segments needs two coupled decisions:

  1. Which user should each segment serve?
    discrete, couples the segments, should change only when the geometry changes
  2. Where should each segment focus?
    continuous, per segment, rate-limited by servo actuation
Why the assignment is hard
  • $|\mathcal{B}|=K^L$: 16 assignments for $K=2$, 256 for $K=4$ ($L=4$)
  • A poor assignment leaves a user served only by residual multipath
  • Servo limits: non-convex reachable set
  • State: noisy position estimates; no pilot-based CSI estimation

Five questions, answered

WHYSpatial information suffices: every part decides from user positions (run time) or a site model (planning), never from pilot-based CSI estimation; the cost is decimeter-level localization and site-model fidelity.
WHATFocal points are the shared interface: one abstraction steers the tiles in the geometric rule, both learned controllers, and the placement optimizer.
HOWLearned, decentralized policies act within servo limits and are trained on received power for several moving users; when segments differ in geometry, learning the assignment beats a fixed split and the best geometric heuristic.
WHEREWhere to install is a decision of its own: a reflector configured once and placed jointly with the APs met the priority-coverage target with one fewer AP (seed mean, small margins).
WHICHMatch the method to the problem. Geometry for one static user or as a warm start; learned policies for run-time multi-user control; direct optimization (PSO + gradient refinement) for once-per-building placement.
In ray-traced simulations, focal points let us use spatial information for both placement and steering, without estimating a channel for every tile.

[1.25 min | 37:15–38:30]

I'll return to the user around the corner. If we know where that user is, the bisector rule tells us how to orient a tile. A focal point lets us use that same construction even when the best place to aim is a decision we need to learn.

With several users, we can learn a local steering policy for each segment. When the segments see the room from different angles, it also pays to learn their assignments. Before installation, when the building is known and the mounting sites are still open, we can optimize the layout directly.

My main conclusion is that spatial information can guide both decisions. In our simulations, a building model tells us where to install the hardware, and user positions tell us where to steer it. Focal points connect those two tasks. With an accurate model and reliable positions, we can do both without estimating a separate channel for every tile.

Slot set by servo rotation time
Order of tens of milliseconds: user speed well above walking pace, so the setting is a stress test of the tracking loop rather than an indoor mobility model.
Slot set by localization update rate
Order of one second: 30 cm per slot is a slow walk, and the servo is no longer the binding constraint.

A slot is one control update. The simulation specifies a displacement of thirty centimeters per slot and leaves the physical duration open. Placement: model approximations, implementation

Model approximations
  • Each tile is a locally planar specular facet: finite-tile edge diffraction is neglected
  • Radio map sums path powers incoherently; it approximates the average over small-scale fading
  • Constructive combining of the $N_rN_c$ tile paths could add up to $10\log_{10}(N_rN_c)$ dB at a point; destructive combining could remove as much
  • Quantifying this needs full-wave simulation or measurement
Implementation
  • Three Ray workers share one RTX 5070 Ti GPU
  • Scene load about 1 s vs. about 0.1 s per radio map, so each worker loads its scene once
  • One PSO+GD run: 1,750 swarm $+$ 30 differentiable evaluations, about 180 s serial
  • Cost scales with evaluations, rays per transmitter, AP count, and grid cells

For the placement maps, we sum the powers of the traced paths incoherently. That approximates power averaged over small-scale fading. A narrowband receiver at one exact point can measure a higher or lower value because path phases matter there. We also model each tile as a planar reflecting facet and omit diffraction at its edges. Measurements or a full-wave model would let us quantify those approximations. Computationally, we reuse each loaded scene across many radio-map evaluations.
