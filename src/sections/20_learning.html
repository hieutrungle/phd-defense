Focal-point abstraction: a segment is steered by 3 coordinates

Illustrative
All tiles of segment $l$ aim at one virtual focal point $f_l \in \mathbb{R}^3$ instead of the user; angles are clipped to servo limits.
$2N_rN_c$ tile angles become $3L$ focal coordinates. Learned control and placement set the focal points.

Follow one colored crosshair. It marks a virtual focal point. We can move it sideways, forward, or up, and it can sit away from the user. In the front view, the tiles of the matching color each turn to aim at that point, up to their servo limits.

This lets us describe the whole 63-tile panel with three focal points. That's nine coordinates in place of 126 separate angle commands. We can now give each segment a manageable decision to learn.

MA-MDP: each agent moves the focal point of one segment

Array partitioned into $L$ disjoint segments $\mathcal{T}_l$; agent $l$ controls focal point $f_{l,t}\in\mathbb{R}^3$.

  • State: $s_t=[u_{1,t},\dots,u_{K,t},\,r_{1,t},\dots,r_{L,t},\,f_{1,t},\dots,f_{L,t}]$user positions, segment centers, focal points
  • Local observation: $o_{l,t}=[u_{b_l,t},\,r_{l,t},\,f_{l,t}]$; assigned user $b_l$ fixed in advance
  • Action: $a_{l,t}\in\mathbb{R}^3$, $\|a_{l,t}\|_\infty\le\delta_{\max}$, $\;f_{l,t+1}=f_{l,t}+a_{l,t}$
  • Shared reward: $R(s_t,a_t)=\frac{1}{K}\sum_{k=1}^{K}P_{r,k}(s_t,a_t)$ (RSSI)
  • Focal points clipped to $\mathcal{F}_l$, angles to $\pm30^\circ$: every action feasible

Run time: positions only; training: received power as the reward. No pilot-based CSI estimation.

Dimensionality reduction
$$R_{\text{complexity}}=\frac{2N_rN_c}{3L}$$
14×
fewer control variables for $N_rN_c=63$ tiles, $K=L=3$
Answers the geometric limits:
servo limits → clipped actions
alignment → received-power reward
several users → one agent per segment

Imagine you're the agent for one segment. You know where your segment is, where it's currently aiming, and where your assigned user is. Every step you choose how far to move the focal point in each of three directions. We bound that move, keep the focal point in its allowed region, and clip the tile angles at thirty degrees.

We describe this as a cooperative multi-agent Markov decision process. Your move changes the power that reaches several users, so during training every agent gets the same score, the mean received power across users. That gives each agent a reason to learn moves that work alongside its neighbors. During operation, the agent needs only its three local positions.

One decision has already been made for you. Your segment keeps the same user for the entire run. Watch for that distinction in the moving example.

Training with MAPPO under CTDE

  • MAPPO: multi-agent proximal policy optimization
  • CTDE (centralized training with decentralized execution) mitigates non-stationarity: global critic in training, local actors at deployment
  • Execution: each actor uses only its local observation; no inter-agent communication
  • Actor and critic: small MLPs, Adam optimizer (settings in backup)

The diagram shows centralized training with decentralized execution. While the actors learn, a shared critic sees the whole scene. That matters because the effect of one agent's move depends on what its neighbors do. Each actor uses the critic's feedback to update its policy. We train them with multi-agent proximal policy optimization, or MAPPO.

The three terms below limit the incentive for large policy updates, train the critic to predict returns, and encourage the actors to explore. Once trained, each actor runs on local positions without contacting the other actors. Here's the hallway where we test them.

Why flat MARL is not enough: a fixed tile-to-user assignment

  • Focal points are learned, but the tile-to-user assignment is fixed in advance (columns 1, 4, 7 → user 1)
  • In this hallway it costs nothing measurable: two groupings both give $-67.60$ dBm, because each user's tiles span the whole aperture
  • It matters when segments differ in geometry (contiguous parts of an array, arrays on different walls) or users $\neq$ segments
  • Choosing it is discrete and combinatorial ($K^L$ options); continuous focal-point actors are not designed for it

From fixed assignment to learned allocation

Two corner arrays: a user can be served by segments with very different geometry, so the assignment now matters.

Serving $K$ users with $L$ segments needs two coupled decisions:

  1. Which user should each segment serve?
    discrete, couples the segments, should change only when the geometry changes
  2. Where should each segment focus?
    continuous, per segment, rate-limited by servo actuation
Why the assignment is hard
  • $|\mathcal{B}|=K^L$: 16 assignments for $K=2$, 256 for $K=4$ ($L=4$)
  • A poor assignment leaves a user served only by residual multipath
  • Servo limits: non-convex reachable set
  • State: noisy position estimates; no pilot-based CSI estimation
Make the user-to-segment assignment a learned decision on its own, slower timescale.

With four segments and four users, each segment can choose any user. That gives 256 assignments. Some leave a user with only the signal that reaches them indirectly. Once we pick an assignment, the servos still have to move each focal point into position. The assignment and the aim are coupled, but they can change at different speeds.

Within the window, each segment follows its assigned user, moving its focal point once per slot from local observations.

HMA-MDP: one objective, a reward for each timescale

High level: allocation (every $T$ slots)
State $s_H=\{u_{1:K},\,r_{1:L},\,f_{1:L}\}$, action $b\in\mathcal{B}$
Reward: concave, every user counts $$R_{\mathrm{sys}}=\frac1K\sum_{k=1}^{K}\ln\bigl(1+[\tilde P_k(t)]^+\bigr)$$ Trained on macro-steps: the discounted return inside each window
Low level: focal points (every slot)
Masked state $s_{L,l}=\{u_{b_l},\,r_l,\,f_l\}$, $\|a_{l,t}\|_\infty\le\delta_{\max}$
Reward: assigned user's power + progress $$R_l(t)=\frac{1}{P_{\mathrm{sc}}}\Bigl[\tilde P_{b_l}(t)+\bigl(\tilde P_{b_l}(t)-\tilde P_{b_l}(t{-}1)\bigr)\Bigr]$$ Second term: potential-based shaping ($\Phi=\tilde P_{b_l}$)

Shared objective: $\max\ \mathbb{E}\bigl[\sum_{t}\gamma^{t}R_{\mathrm{sys}}(s(t),b(t))\bigr]$ s.t. $b(t)\in\mathcal{B}$ at $t\in\{0,T,2T,\dots\}$, $f_l(t)\in\mathcal{F}_l$, servo limits.

$\tilde P_k$: shifted received power (dBm); $P_{\mathrm{sc}}$: scale (backup). Unlike flat MARL (clipping), a move that would push any tile past its limit is rejected.

The allocator on the left has to care about everyone. Its score gives more credit for raising a weak user's signal than for the same increase on an already strong link. We add up those rewards, with discounting, across the allocation window.

On the right, each segment gets quicker feedback. It earns credit for its assigned user's received power and for improving that power since the last slot. If a proposed move would push even one tile past its servo limit, the segment stays put. Geometry can also help the allocator learn where to start.

We train the segments with MAPPO. For the allocator, PPO treats each assignment window as one step. At first, we give the allocator a hint. Its scores favor segments close to a user with a gentle reflection angle. Then we turn the hint off and continue learning from received power. If we reassign every slot, the local agent can experience a new user as a sudden jump in position. Wait a hundred slots and the allocator gets only one decision per episode. Of the intervals we tested, ten slots gave the highest training reward for four users. The two longest intervals were still improving at the training cutoff.

What allocation buys, and what it cannot fix

  • The high-level controller assigns each reflector segment to a user every $T$ slots (10 slots in this experiment).
  • The low-level controllers adjust their segments' focal points every slot to focus each reflected beam on its assigned user.
Answered (HOW): The learned controllers use positions alone to decide which user each reflector segment serves and where to aim its beam. For four moving users in simulation, adapting the assignments raised mean received power by 5.84 dB over a fixed split.
Opens (WHERE): more tiles at a fixed site saturate: where should the AP and the arrays be installed? → placement.

Every ten slots, the high-level controller decides who each segment serves. While that assignment holds, each low-level controller adjusts its segment's focal point every slot to follow the moving user. For four users, learning the assignment gained nearly six decibels over a fixed split. Both approaches take the mounting sites as given. What if we could choose where to install the panels?
