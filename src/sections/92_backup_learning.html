HMARL per-user vs. aggregate received power

The aperture is passive and every controlled tile reaches every user, so there is no fixed power budget to divide; the per-user loss is consistent with competition for steering range, though no experiment separates the two.

Backup: what happens when the user count doubles. Per-user RSSI: the median drops by about 2.5 dB from two to four users; the HMARL-C run means differ by 1.16 dB, because the distributions differ in shape. Aggregate power is slightly higher with four users, up to about 1 dB. The CDFs come from the 300-slot HMARL-C deployment runs.

HMARL reward sensitivity and the role of $P_{\mathrm{off}}$

Path-loss compensated measurement:

$$\tilde P_k^{(n)}=\tilde P_k+10\,n\log_{10}d_k$$
  • Larger $n$ favors distant users
  • Medians span $-65.23$ to $-64.42$ dBm (0.81 dB)
  • $P_{\mathrm{off}}=80$ dB also sets the fairness weighting: a user at $-75$ dBm carries $2.7\times$ the marginal weight of one at $-65$ dBm ($1.38\times$ at $P_{\mathrm{off}}=100$ dB); not swept

Backup: reward design. Training was repeated with the linear received power scaled by the user's distance to the power n, n from 0 to 4, before conversion to dBm, which progressively favors distant users. The five deployment CDFs nearly coincide: medians span 0.81 dB. The offset P-off of 80 dB is the smallest round value that keeps the shifted power non-negative over the observed minus 60 to minus 80 dBm range, but it also sets how strongly the log utility favors weak users; that weighting was not swept.

HMARL: what one slot means physically

  • The study is simulation-only and does not fix a slot duration; the protocol is specified in slots
  • Users advance 30 cm per slot and the focal point may move $\delta_{\max}=0.3$ m per axis per slot: the actuator is provisioned to match the assumed user displacement
Slot set by servo rotation time
Order of tens of milliseconds: user speed well above walking pace, so the setting is a stress test of the tracking loop rather than an indoor mobility model.
Slot set by localization update rate
Order of one second: 30 cm per slot is a slow walk, and the servo is no longer the binding constraint.

Either way, mechanical rotation time and quasi-static geometry confine deployment to low-mobility indoor use; fixing the slot duration requires hardware-in-the-loop validation.

Backup: if asked how fast the users move in real time. There is no physical slot duration in this study; two consistent readings exist, and which constraint binds depends on hardware that has not yet been tested in the loop.
